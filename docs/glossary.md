# 용어

문서는 아래 표의 표준 용어를 사용한다. 화면 표기가 표준 용어와 다른 항목은 "화면 표기" 열에 병기하며, 문서에서 화면의 메뉴·버튼을 지칭할 때는 화면 표기를 그대로 인용한다. 화면 문구의 출처는 설치 마법사(`frontend-react/src/installer-app/i18n/`)와 본 앱(`frontend-react/src/i18n/locales/`)의 번역 파일이다.

| 용어 | 영어 | 화면 표기 | 정의 |
|---|---|---|---|
| 설치 관리자 | installer | 설치 관리자 | 설치, 구역 활성화·비활성화, 업데이트, 인증서 발급을 담당하는 컨테이너(`jw-installer`). 설치 완료 후에도 상주한다 |
| 설치 마법사 | setup wizard | 설치 마법사 | 설치 관리자가 8443 포트로 제공하는 웹 UI. 설치가 완료되면 잠긴다 |
| 설치 토큰 | install token | 설치 토큰 | 설치 마법사 접근에 필요한 12자리 값. 유효 기간은 24시간이며 `jw token` 으로 재발급한다 |
| 설치 폴더 | install folder | — | 설치 관리자에 `/data` 로 마운트한 호스트 폴더(예: `/opt/just-workspace`). 스택 파일(`stack/`)과 상태(`state/`)를 보관한다 |
| 응답 파일 | answers file | 답변 파일 | 설치 마법사의 입력값을 기록한 JSON 파일. 무인 설치에 사용한다 |
| 사전 점검 | preflight | 사전 점검 | 설치 전에 서버의 요구 조건 충족 여부를 확인하는 검사. 결과는 통과 · 주의 · 실패 |
| 구역 | zone | 구역 | 설치 및 활성화·비활성화의 기능 단위(메일, 채팅, 회의 …). 선언은 `backend/app/zones.json` |
| 기본 구역 | core | 기본 구역 | 항상 설치되는 구역 — 로그인, 관리, 대시보드, 파일 |
| 선택 애드온 | add-on | 선택 애드온 | 구역과 동일한 방식으로 활성화·비활성화하는 부가 기능 — SSO·LDAP 제공, 격리 브라우저 |
| 프리셋 | preset | 묶음 | 설치 마법사가 제공하는 구역 조합 — 최소 · 협업 · 전체 |
| 접속 주소 | access address | 접속 주소 | 사용자가 브라우저에 입력하는 주소(도메인 이름) |
| 네트워크 구성 | network type | 연결 형태 | 서버의 인터넷 연결 방식 — 공인 주소 직접 연결 · 공유기(NAT) 하단 · 기존 프록시 하단 |
| 프런트 프록시 | front proxy | 앞단 프록시 | 이 서버의 전단에서 TLS 를 종단하고 요청을 전달하는 리버스 프록시(reverse proxy) |
| 임시 인증서 | temporary certificate | 임시 인증서 | 설치 관리자가 생성한 자체 서명 인증서. 브라우저에 경고가 표시된다. 이후 발급 또는 업로드한 인증서로 교체한다 |
| 파일 저장 위치 | file storage location | 파일 저장 위치 | 파일 탭의 문서, 채팅 첨부, 메일 첨부 보관본의 저장 위치 — 이 서버의 디스크 또는 네트워크 저장소(NFS) |
| 저장소 마커 | storage marker | 저장소 표식 | 저장소 루트에 두는 파일(`.jw-storage`). 이 파일이 확인되지 않으면 파일 쓰기를 거부한다 |
| 연동 보류 | connection pending | 연결 보류 | 구역은 활성화되었으나 워크스페이스와의 연동(코드 저장소의 로그인 연동)이 보류된 상태 |
| 채널 | channel | 채널 | 업데이트 배포 경로 — Stable(화면 표기: 안정판) · Beta(화면 표기: 시험판) |
| 릴리스 | release | 릴리스 | 특정 버전의 이미지 집합과 그 목록 파일(manifest) |
| 사전 공지 | notice | 예고 | 업데이트·복원 시작 전 5분간 전체 사용자 화면에 표시되는 배너 |
| 점검 모드 | maintenance | 점검 | 업데이트·복원 진행 중 일반 사용자의 요청을 차단하는 상태 |
| 롤백 | rollback | 되돌림 | 실패한 업데이트를 이전 버전과 직전 백업의 DB 로 복원하는 작업 |
| 복원 지점 | restore point | 복원 지점 | 업데이트 직전에 생성한 백업. 관리 › 업데이트 › 되돌림에서 선택해 해당 시점으로 복원한다 |
| 오프라인 번들 | offline bundle | 묶음 파일 | 인터넷에 연결되지 않은 서버의 업데이트에 사용하는 tar 파일(`just-workspace-<버전>-offline.tar`) |
| 백업 파일 | backup file | 백업 파일 | 백업 폴더를 단일 파일로 패키징한 것(`.jwbak`) |
| 백업에서 복원 | restore from backup | 백업에서 복원 | 설치 마법사의 시작 방식 중 하나. 다른 서버에서 생성한 백업으로 이 서버를 구성한다 |
| 스키마 버전 | schema version | 스키마 버전 | 데이터베이스 구조의 버전 번호. 코드가 요구하는 번호와 일치해야 서버가 기동한다 |
| 내부 대역 | internal subnet | 내부 대역 | 컨테이너 간 통신에 사용하는 사설 대역(기본 `172.28.0.0/24`) |
| 내부 API | internal API | — | 설치 관리자가 backend 에만 제공하는 API(8444). 호스트에 게시하지 않는다 |
| 플러그인 | plugin | 플러그인 | 서버에 설치해 기능을 추가하는 확장 모듈. 서버 권한으로 실행된다 |

문서 전반에서 다음 표기를 따른다.

| 표기 | 의미 |
|---|---|
| 외부 이미지 | 본 프로젝트가 빌드하지 않고 원 배포처에서 직접 pull 하는 제3자(third-party) 컨테이너 이미지 |
| 자체 빌드 이미지 | 본 프로젝트가 이 리포의 소스로 빌드해 배포하는 컨테이너 이미지 |
| 활성화 · 비활성화 | 구역·기능의 사용 여부 전환(화면 표기: 켜기 · 끄기) |
| 기동 · 중지 | 컨테이너·서비스의 실행 상태 전환 |
| 신뢰 저장소 | 신뢰하는 CA 인증서의 집합(trust store) |

"구역"과 compose 의 "프로파일"은 다른 개념이다. 프로파일(`COMPOSE_PROFILES`)은 기동할 컨테이너를 지정하는 compose 의 용어이며, 하나의 구역이 여러 프로파일을 활성화하거나(회의) 프로파일을 전혀 사용하지 않을 수 있다(채팅). 사용자에게 노출되는 단위는 구역이다.
