# 설치 안내

본 문서는 Just Workspace 를 서버에 설치하는 관리자를 대상으로 한다. 설치 관리자를 단일 명령으로 기동하고, 나머지 항목은 브라우저의 설치 마법사에서 구성한다.

- 설치 관리자의 구조·API·응답 파일의 전체 항목: [installer.md](installer.md)(기술 문서).
- 설치 관리자 없이 `docker compose` 로 직접 기동하는 절차: [deployment.md](deployment.md).
- 설치 후 운영: [operate.md](operate.md). 용어 정의: [glossary.md](glossary.md).

## 1. 시스템 요구 사항 (System Requirements)

### 서버

| 항목 | 조건 |
|---|---|
| 운영 체제 | 리눅스, x86_64. Windows·macOS 의 Docker Desktop 은 지원하지 않는다 |
| Docker Engine | 24.0 이상 |
| 프로세서 | 2코어 이상 |
| 메모리 | 4 GB 이상이며, 선택할 구역의 권장 메모리 합계 이상 |
| 디스크 | 여유 10 GB 이상(20 GB 미만은 경고) |
| 시각 | 동기화 상태일 것(불일치 시 인증서 발급과 로그인이 실패할 수 있다) |

Docker Compose 의 별도 설치는 불필요하다 — 설치 관리자 이미지에 포함된 것을 사용한다.

구역별 권장 메모리(출처는 `backend/app/zones.json`):

| 구역 | 권장 메모리 |
|---|---|
| 기본(항상 설치) | 4 GB |
| 메일 | +1 GB |
| 채팅 · 일정·연락처·할 일 | 추가 없음 |
| 문서 편집·위키·게시판 | +2 GB |
| 회의 | +1 GB |
| 코드 저장소 | +0.5 GB |
| AI 도우미 | +1 GB |
| 애드온: SSO·LDAP 제공 | +0.5 GB |
| 애드온: 격리 브라우저 | +0.1 GB |

프리셋 기준으로는 최소 4 GB, 협업 7 GB, 전체 9.5 GB 다. "4 GB 서버"와 같이 실제로 인식되는 메모리가 소폭 부족한 경우(차이 8% 이내)는 4 GB 로 간주한다.

### 접속 주소와 DNS

**접속 주소**는 사용자가 브라우저에 입력하는 주소다(예: `workspace.example.com`). 도메인 이름 사용을 기본으로 하며, 시험 목적이라면 IP 주소로도 설치할 수 있다(이 경우 임시 인증서만 사용 가능하다).

설치 전에 DNS 에 A 레코드를 등록한다.

| 이름 | 필요 조건 |
|---|---|
| `workspace.example.com` (접속 주소) | 항상 |
| `mail.<메일 도메인>` | 메일 구역에서 내장 메일 서버를 사용하는 경우 |
| `turn.<접속 주소>` | 회의 구역에서 중계 서버를 사용하는 경우 |
| `rbi.<접속 주소>` | 격리 브라우저 애드온을 사용하는 경우 |

인증서를 자동 발급하는 경우 위 표에서 해당하는 이름이 **모두** 인증서에 포함된다. 그중 DNS 에 등록되지 않은 이름이 하나라도 있으면 발급 전체가 실패한다.

내장 메일 서버를 사용하는 경우 메일 도메인에 레코드 5개(MX, A, SPF, DKIM, DMARC)가 추가로 필요하다. 값은 마법사의 메일 화면에 표시된다 — 설치 시점에 전부 등록하지 못하더라도 설치는 계속 진행된다.

### 포트

외부에서 이 서버로의 인바운드 접속이 허용되어야 하는 포트다. 클라우드의 보안 그룹, 서버 방화벽, 공유기에서 개방한다.

| 구역 | 포트 | 용도 |
|---|---|---|
| 기본 | 80/tcp | 인증서 발급과 접속 |
| | 443/tcp | 접속(프런트 프록시 하단 구성에서는 프록시가 수신한다) |
| 메일(내장 메일 서버) | 25/tcp | 메일 수신 |
| | 465/tcp, 587/tcp | 메일 발신 |
| | 993/tcp | 메일 조회(IMAP) |
| 회의 | 7882-7892/udp | 영상과 음성 |
| | 7881/tcp | 영상과 음성(UDP 가 차단된 참가자) |
| | 3478/udp | 중계 |
| | 4433/udp | 무손실 오디오를 활성화한 경우에 한함 |
| 코드 저장소 | 2222/tcp | 저장소 접속(SSH) |
| SSO·LDAP 제공 | 636/tcp | 계정 조회(LDAPS). 평문 389 는 기본적으로 서버 자신에게만 개방된다 |

- 설치 진행 중에는 **8443/tcp**(설치 마법사)에도 접근 가능해야 한다. 설치가 완료되면 마법사는 잠기며, 이 포트는 방화벽에서 차단해도 무방하다.
- 이 서버가 접속을 직접 수신하는 구성에서는 회의 중계의 보안 연결이 **5349/tcp** 에서 제공된다(443 은 웹이 사용한다).
- 통신사가 25번 포트를 차단하는 회선에서는 내장 메일 서버로 메일을 송수신할 수 없다. 이 경우 외부 발신 서버를 선택한다.

### 네트워크 구성

마법사가 서버의 주소를 기준으로 자동 감지하나, 사전에 파악해 둘 것을 권장한다.

| 네트워크 구성 | 정의 | 준비 사항 |
|---|---|---|
| 공인 주소에 직접 연결 | 클라우드 서버와 같이 서버가 공인 주소를 직접 보유한다 | 위 포트를 방화벽에서 개방한다 |
| 공유기 뒤 (포트 포워딩) | 서버가 사설 주소를 사용하며 전단에 공유기가 있다 | 공유기에서 위 포트를 이 서버로 포워딩한다. 마법사가 구역 선택 후 대상 목록을 표시한다 |
| 기존 프록시 뒤 | 기존에 운용 중인 리버스 프록시가 전단에 있다 | 프록시의 주소(또는 대역). 아래 참조 |

프록시 하단 구성의 유의 사항:

- 프록시를 경유하는 것은 웹 접속에 한한다. 이 서버는 80번에서 평문으로 수신하며, 인증서는 프록시가 처리한다.
- 프록시는 접속자의 주소를 `X-Real-IP` 헤더로 전달해야 한다(`X-Forwarded-For` 만으로는 접속자 주소로 인정하지 않는다). WebSocket 과 대용량 파일 업로드도 통과시켜야 한다. 마법사의 프록시 주소 화면에 nginx 설정 예시가 있다.
- 메일·회의·코드 저장소(SSH)·LDAP 포트는 프록시를 경유하지 않고 이 서버로 직접 인입되어야 한다.

### 인증서

| 방식 | 적용 대상 | 조건 |
|---|---|---|
| 자동 발급 (Let's Encrypt) | 직접 연결·공유기 뒤 | 접속 주소가 도메인이고 이 서버를 가리켜야 하며, 외부에서 80번으로 접근 가능해야 한다 |
| 보유 인증서 업로드 | 직접 연결·공유기 뒤 | 인증서(중간 인증서까지 연결한 PEM)와 개인 키(암호가 설정되지 않은 PEM). 접속 주소가 포함되어 있어야 한다. 사내 CA 등 **사설 CA** 가 발급한 인증서인 경우 해당 CA 인증서도 준비한다 — 없으면 코드 저장소의 로그인 연동이 보류 상태로 남는다(설치 후 CA 만 별도로 업로드할 수 있다) |
| 프록시가 처리 | 기존 프록시 뒤 | 프록시가 인증서를 보유한다. 이 서버에서는 발급하지 않는다 |
| **임시 인증서**로 설치 후 추후 발급 | 접속 주소가 아직 이 서버를 가리키지 않거나 확인할 수 없는 경우, 주소가 IP 인 경우, 자동 발급이 실패한 경우 | 없음 |

임시 인증서는 자체 서명 인증서이므로 브라우저에 경고가 표시된다. 설치 완료 후 관리 › 보안·SSL 의 인증서 카드에서 발급하거나 업로드한다([operate.md](operate.md#5-인증서)). 임시 인증서를 사용하는 동안에는 코드 저장소의 로그인 연동이 "연동 보류" 상태로 유지된다.

### 파일 저장 위치

파일 탭의 문서, 채팅 첨부, 메일 첨부 보관본의 저장 위치다. **설치 후 이전하려면 전체 복사가 필요하므로 설치 시점에 확정한다.** 데이터베이스와 메일함은 선택과 무관하게 이 서버의 디스크에 저장된다.

| 선택 | 준비 사항 |
|---|---|
| 이 서버의 디스크 | 없음. 필요 시 기존 폴더를 지정할 수 있다(절대 경로, 쓰기 가능해야 한다) |
| 네트워크 저장소 (NFS) | 아래 참조 |

NFS 요구 사항:

- **NFSv4.1** 을 지원하는 NAS 또는 파일 서버. v3 만 지원하는 서버는 마운트할 수 없다.
- 이 서버의 주소에 **읽기·쓰기**를 허용한 공유(export) 경로.
- 공유의 루트에 **uid/gid `1000:1000`** 의 쓰기 권한이 있을 것. 설치 관리자는 공유 루트의 소유자·권한을 변경하지 않는다.
- 이 서버에서 NAS 의 TCP 2049 에 접근 가능할 것.

마법사는 5개 항목(도달 가능 여부, 마운트 가능 여부, 쓰기·읽기·삭제, 파일 잠금, 여유 공간)을 검사하며, 앞의 4개 항목을 통과해야 다음 단계로 진행한다.

## 2. 설치 및 구성 절차 (Installation & Configuration)

### 설치 관리자 기동

```bash
docker run -d --name jw-installer --restart unless-stopped \
  -p 8443:8443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /opt/just-workspace:/data \
  -e JW_HOST_DIR=/opt/just-workspace \
  -e JW_INSTALLER_VERSION=1.0.0 \
  ghcr.io/just-workspace/just-workspace-installer:1.0.0

docker logs jw-installer
```

- `/opt/just-workspace` 가 **설치 폴더**다. 다른 경로를 사용할 수 있으나 `-v <폴더>:/data` 와 `-e JW_HOST_DIR=<폴더>` 는 반드시 동일한 경로여야 한다.
- `-e JW_INSTALLER_VERSION=<버전>` 에는 **이미지 태그와 동일한 버전**을 지정한다. 설치 관리자가 설치할 제품 버전이다. Stable 이미지는 검증을 완료한 Beta 이미지를 재빌드하지 않고 그대로 승격한 것이므로, 이 값을 지정하지 않으면 이미지에 내장된 Beta 버전 문자열(`1.0.0-beta.N`)을 자신의 버전으로 인식한다(이 경우 설치 관리자 로그의 첫머리에 알림 1줄이 출력된다).
- `-e JW_PUBLIC_HOST=<서버 주소>` 를 지정하면 로그의 주소와 설치 관리자의 인증서에 해당 값을 사용한다.
- 위 명령의 `1.0.0` 은 Stable 버전의 예시이다. 버전은 릴리스 페이지에 공개된 최신 값을 사용하며, 이미지 태그와 `JW_INSTALLER_VERSION` 두 곳에 동일하게 지정한다. Stable 공개 이전에는 공개된 Beta 버전(예: `1.0.0-beta.4`)을 지정한다 — Beta 버전으로 설치한 서버는 Beta 채널의 업데이트를 수신한다. 공개 이미지를 사용하지 않는 경우 [소스에서 빌드해 설치](#소스에서-빌드해-설치)한다.

로그에 다음과 같은 줄이 출력된다.

```
 브라우저에서 여세요:  https://<서버 주소>:8443/?token=XXXXXXXXXXXX
 SHA-256 지문: AB:CD:…
```

해당 주소를 브라우저로 연다. 설치 관리자의 인증서는 자체 서명 인증서이므로 경고 화면이 표시된다 — 경고 화면에서 인증서의 SHA-256 지문을 로그의 값과 대조한 후 진행한다.

### 설치 마법사 화면 구성

좌측의 단계 목록은 선택한 값에 따라 증감한다. 브라우저를 닫아도 입력한 값은 서버에 보존되며, 재접속하면 이어서 진행한다.

| 화면 | 수행 내용 |
|---|---|
| 설치 토큰 | 로그의 주소로 접속한 경우 생략된다. 주소를 직접 입력한 경우 토큰(영문 대문자와 숫자 12자리)을 입력한다 |
| 사전 점검 | 서버를 점검한다. **실패** 항목이 없어야 다음 단계로 진행한다. **주의** 항목은 조치 없이 진행할 수 있다 — [문제 해결](#사전-점검-실패-시-조치) |
| 시작 방식 | **새로 설치** · **빠른 설치** · **백업에서 복원** 중 하나를 선택한다. 응답 파일을 이용한 설치 방법도 이 화면에서 안내한다 |
| 접속 주소와 네트워크 구성 | 접속 주소를 입력하면 이 서버를 가리키는지 확인한다. 네트워크 구성과 인증서 방식을 선택한다 |
| 프록시 주소 | (기존 프록시 뒤인 경우) 프록시의 주소 또는 대역. 복수 값은 쉼표로 구분한다 |
| 인증서 올리기 | (인증서를 업로드하는 경우) 인증서와 개인 키 파일, 그리고 사설 CA 가 발급한 인증서인 경우에 한해 "CA 인증서(선택)". 접속 주소·키 쌍·만료일·발급 CA 를 즉시 검증한다 |
| 파일 저장 위치 | 이 서버의 디스크 또는 네트워크 저장소 (NFS) |
| 구역 선택 | 프리셋(최소·협업·전체)을 선택하거나 개별 선택한다. 권장 메모리 합계가 서버 메모리를 초과하면 다음 단계로 진행할 수 없다. 선택 애드온도 이 화면에서 선택한다 |
| 포트 포워딩 안내 | (공유기 뒤인 경우) 공유기에서 이 서버로 포워딩할 포트 목록 |
| 메일 | (메일 구역) 내장 메일 서버 + 메일 도메인, 또는 외부 발신 서버(SMTP). 내장 메일 서버인 경우 등록할 레코드 5개와 현재 상태를 표시한다 |
| 회의 | (회의 구역) 공인 주소, 중계 서버 사용 여부, 무손실 오디오 |
| AI 도우미 | (AI 도우미 구역) 즉시 연결(제공자와 키) 또는 추후 연결 |
| 코드 저장소 | (코드 저장소 구역) 설치할 버전 — 검증된 버전 · 최신 · 직접 지정 |
| 관리자 계정 | 이름, 아이디, 비밀번호(12자 이상). 해당 워크스페이스의 최초 계정이다 |
| 요약 | 선택 내용, 유의 사항, 개방되는 포트. **이 시점까지 서버에 변경 사항은 없다.** 고급 설정(내부 네트워크 대역)과 "응답 파일 다운로드"가 이 화면에 있다 |
| 적용 | 설치를 실행하면 단계별로 진행한다: 설정 파일과 비밀 키 생성 → 저장소 연결 → 이미지 pull → 데이터베이스 준비 → 인증서 발급 → 구역 기동 → 관리자 계정 생성 → 마법사 잠금 |
| 완료 | 접속 주소와 후속 작업 |

적용은 브라우저를 닫아도 계속 진행된다. 특정 단계가 실패하면 원인과 조치 방법이 화면에 표시되며, 조치 후 **"이 단계부터 다시"** 를 선택하면 완료된 단계는 재실행하지 않고 이어서 진행한다. 인증서 자동 발급이 실패하면 임시 인증서로 계속 진행하는 선택지가 제시된다.

비밀값(암호화 키, 데이터베이스 비밀번호, 구역 간 공유 키)은 설치 관리자가 생성한다. 관리자가 직접 지정하는 값은 관리자 비밀번호뿐이다.

### 빠른 설치

시작 방식에서 **빠른 설치**를 선택하면 접속 주소, 메일, 관리자 계정만 입력받는다. 나머지 항목에는 감지한 값과 기본값을 적용한다.

- 네트워크 구성: 감지한 값.
- 인증서: 접속 주소가 이 서버를 가리키면 자동 발급, 그렇지 않으면 임시 인증서.
- 파일 저장 위치: 이 서버의 디스크.
- 구역: 협업 프리셋. 서버 메모리가 부족하면 최소 프리셋으로 하향하고 메일 화면을 생략한다.

구역은 설치 후 관리 › 구역에서 활성화·비활성화할 수 있다.

### 무인 설치 (응답 파일)

마법사의 입력값과 동일한 내용을 JSON 파일 하나에 기록해 화면 없이 설치한다. 요약 화면의 "응답 파일 다운로드"로 현재 선택한 값을 파일로 저장할 수도 있다(비밀번호와 키는 포함되지 않는다).

최소 프리셋, 임시 인증서:

```json
{
  "version": 1,
  "mode": "new",
  "access": { "domain": "workspace.example.com", "network": "direct", "cert": "temporary" },
  "storage": { "kind": "local" },
  "preset": "minimal",
  "addons": [],
  "admin": { "name": "관리자", "username": "admin" }
}
```

협업 프리셋, 자동 발급, 내장 메일 서버:

```json
{
  "version": 1,
  "mode": "new",
  "access": { "domain": "workspace.example.com", "network": "direct", "cert": "auto" },
  "storage": { "kind": "local" },
  "preset": "collab",
  "addons": [],
  "mail": { "kind": "builtin", "mail_domain": "example.com" },
  "admin": { "name": "관리자", "username": "admin" }
}
```

NFS 저장소는 `"storage": { "kind": "nfs", "server": "192.168.10.30", "export": "/volume1/workspace" }`, 프록시 하단 구성은 `"access": { "domain": "…", "network": "proxy", "proxy_addresses": ["192.168.10.5"], "cert": "proxy" }` 로 기술한다. 전체 항목은 [installer.md](installer.md) 4절, 견본은 `installer/e2e/answers/` 에 있다.

파일을 설치 폴더에 배치한 후(컨테이너 내부에서는 `/data/` 하위 경로로 인식된다) 실행한다. 관리자 비밀번호 등의 비밀값은 파일에 기록하지 않고 환경변수로 전달할 수 있다 — `JW_ADMIN_PASSWORD`, `JW_MAIL_PASSWORD`, `JW_AI_API_KEY`.

```bash
# /opt/just-workspace/answers.json 에 응답 파일, /opt/just-workspace/admin.env 에 JW_ADMIN_PASSWORD=<비밀번호> (권한 600)
docker exec jw-installer jw apply --answers /data/answers.json --dry-run     # 검증만 수행 — 변경 사항 없음
docker exec --env-file /opt/just-workspace/admin.env jw-installer jw apply --answers /data/answers.json
rm /opt/just-workspace/admin.env

docker exec jw-installer jw status          # 단계별 상태
```

### 소스에서 빌드해 설치

수정한 소스로 설치하거나 공개 이미지를 사용하지 않는 경우에 해당한다. 설치 대상 서버에서 다음을 실행한다.

```bash
git clone https://github.com/just-workspace/just-workspace.git
cd just-workspace
bash installer/e2e/build-images.sh      # 자체 빌드 이미지 전체 + 설치 관리자를 소스에서 빌드한다

docker run -d --name jw-installer --restart unless-stopped \
  -p 8443:8443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /opt/just-workspace:/data \
  -e JW_HOST_DIR=/opt/just-workspace \
  -e JW_REGISTRY=localhost \
  -e JW_INSTALLER_VERSION=$(cat VERSION) \
  just-workspace-installer:$(cat VERSION)
```

- 빌드에는 서버에 git 과 Docker Compose 플러그인(`docker compose`)이 필요하다. 상당한 시간과 디스크 공간이 소요된다.
- 스크립트는 `localhost/just-workspace-<이름>:<버전>` 과 `just-workspace-installer:<버전>` 을 생성한다(검수에 사용하는 것과 동일한 스크립트다). `JW_REGISTRY=localhost` 는 설치 관리자가 서버에 이미 존재하는 해당 이미지를 사용하도록 지정한다.
- 외부 이미지(데이터베이스, 문서 편집기 등)는 이 경우에도 원 배포처에서 직접 pull 한다.
- 격리 브라우저 애드온의 세션 이미지는 용량이 크므로 별도로 빌드한다: `bash installer/e2e/build-images.sh rbi-mirror`.
- 설치 관리자 이미지에는 리포의 `installer/keys/*.pub`(업데이트 채널의 서명 검증용 공개 키)가 포함된다. 해당 폴더를 비운 상태로 빌드한 경우 관리 › 업데이트가 "구성되지 않음"으로 표시된다. 다른 채널을 사용하려면 `docker exec -i jw-installer jw update-key add - < release.pub` 로 해당 채널의 공개 키를 등록한다(설치 폴더의 키가 이미지의 키보다 우선한다) — [operate.md](operate.md#2-업데이트)의 "업데이트 확인이 구성되지 않았습니다".

## 3. 설치 후 작업

완료 화면에 해당 항목이 안내된다.

1. **접속 주소로 접속해 로그인한다.** 설치 마법사는 잠긴 상태이며, 이후의 설정 변경은 관리 화면에서 수행한다.
2. **인증서 발급** — 임시 인증서로 설치한 경우 접속 주소가 이 서버를 가리키도록 구성한 후 관리 › 보안·SSL 의 인증서 카드에서 발급한다.
3. **누락된 메일 레코드 등록** — 관리 › 구역의 메일 설정에서 등록 대상 레코드와 현재 상태를 재확인할 수 있다.
4. **백업 설정** — 관리 › 저장소·백업에서 예약 백업을 활성화한다. 백업 사본은 서버 외부에도 1부 보관한다.
5. **사용자 초대** — 메일 주소로 초대하거나 초대 링크를 생성한다.
6. **8443 차단** — 설치 마법사의 포트는 방화벽에서 차단해도 무방하다. 설치 관리자 컨테이너(`jw-installer`)는 **삭제하지 않는다** — 구역 활성화·비활성화, 업데이트, 인증서 갱신 후속 처리를 이 컨테이너가 담당한다.

## 4. 문제 해결

### 사전 점검 실패 시 조치

| 항목 | 통과 조건 | 미충족 시 조치 |
|---|---|---|
| Docker Engine | 24.0 이상 | (실패) Docker 를 업그레이드한다. "Docker 에 연결하지 못했습니다"가 표시되면 Docker 의 실행 여부와 `docker run` 의 `-v /var/run/docker.sock:/var/run/docker.sock` 지정 여부를 확인한다 |
| Docker Compose | 2.20 이상 | (실패) 설치 관리자 이미지에 포함된 것을 사용하므로 공식 이미지에서는 발생하지 않는다 |
| 프로세서 | 2코어 이상 | (실패) 코어 수를 증설한다 |
| 메모리 | 4 GB 이상, 선택한 구역의 권장 합계 이상 | (실패) 구역을 축소하거나 서버 메모리를 증설한다 |
| 프로세서 종류 | x86_64 | (실패) x86_64 서버에 설치한다 |
| 디스크 여유 공간 | 10 GB 이상 | (실패) 미사용 Docker 이미지와 파일을 삭제한다. 20 GB 미만은 주의 |
| 시간 동기화 | 동기화됨 | (주의) 서버의 시간 동기화(chrony, systemd-timesyncd 등)를 활성화한다 |
| 웹 포트 80 · 443 | 미사용 | (실패) 해당 포트를 점유한 다른 프로그램(다른 웹 서버 등)을 중지한다. 443 은 이 서버가 접속을 직접 수신하는 경우에만 검사한다 |
| 메일 포트 25 | 미사용 | (주의) 내장 메일 서버를 사용하려면 해당 프로그램(호스트의 postfix 등)을 먼저 중지한다. 메일을 사용하지 않으면 조치 없이 진행한다 |
| 내부 네트워크 대역 | 서버의 다른 네트워크와 중복되지 않음 | (실패) 요약 화면의 고급 설정에서 다른 /24 대역으로 변경한다(기본 `172.28.0.0/24`) |
| 인터넷 연결 · 이미지 저장소 | 도달 가능 | (주의) 이미지가 이 서버에 이미 존재하면 진행할 수 있다 |
| SELinux | (정보) | 상태만 표시한다. SELinux 가 활성화된 배포판에서의 설치는 아직 검증되지 않았다 |

### 설치 토큰 만료 및 분실

설치 토큰은 생성 후 24시간이 경과하면 만료된다. 5회 오입력 시 30초간 입력이 차단된다. 다음 명령으로 재발급한다.

```bash
docker exec jw-installer jw token
```

새 토큰이 포함된 주소가 출력된다. 기존 토큰은 무효화되며, 입력해 둔 값은 유지된다.

### 적용 실패 시 조치

- 화면에 표시된 원인을 조치한 후 **"이 단계부터 다시"** 를 선택한다. "로그 다운로드"로 해당 단계의 로그를 저장할 수 있다.
- 로그는 서버의 `<설치 폴더>/state/logs/<단계>.log` 에도 기록된다. 식별된 비밀값은 `***` 로 마스킹된다.
- 터미널에서는 `docker exec jw-installer jw status` 와 `docker logs jw-installer` 로 확인한다.
- 이미지 pull 에 실패한 경우 서버의 아웃바운드 인터넷 연결을 확인한다.
- 인증서 자동 발급에 실패한 경우 접속 주소(및 `mail.`·`turn.`·`rbi.` 이름)가 이 서버를 가리키는지, 외부에서 80번으로 접근 가능한지 확인한다. 긴급한 경우 임시 인증서로 계속 진행하고 추후 발급한다.

### 재설치

```bash
docker exec jw-installer jw reinstall          # 삭제 대상 목록만 표시한다
docker exec jw-installer jw reinstall --yes    # 삭제 후 설치 관리자를 재시작한다
docker logs jw-installer                       # 마지막에 새 설치 토큰이 출력된다
```

**계정·파일·메일·대화가 전부 삭제된다.** 워크스페이스의 컨테이너·볼륨·내부망과 설치 폴더의 `stack`·`state` 가 삭제 대상이다. 파일 저장 위치가 NFS 또는 지정 폴더인 경우 그 안의 파일은 삭제하지 않는다(단, 새 설치의 계정과 연계되지 않는다).

### 관리자 비밀번호 분실

```bash
docker exec jw-installer jw reset-admin <아이디>                  # 임시 비밀번호가 화면에 1회 출력된다
docker exec jw-installer jw reset-admin <아이디> --disable-2fa    # 인증 앱도 분실한 경우
```

관리자 계정에 한해 사용한다. 해당 계정의 활성 세션은 전부 종료된다. 일반 계정의 비밀번호는 관리 화면에서 재설정한다.

### "설치가 이미 완료되었습니다" 메시지

설치가 완료된 서버의 8443 은 잠긴 상태다. 설정은 접속 주소로 로그인한 후 관리 화면에서 변경한다.
