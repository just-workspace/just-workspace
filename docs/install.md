# 설치 안내

Just Workspace 를 서버에 설치하는 사람을 위한 문서다. 설치 관리자를 한 줄로 띄우고, 브라우저의 설치 마법사에서 나머지를 정한다.

- 설치 관리자의 구조·API·답변 파일의 모든 항목은 [installer.md](installer.md)(기술 문서).
- 설치 관리자 없이 `docker compose` 로 직접 띄우려면 [deployment.md](deployment.md).
- 설치한 뒤의 운영은 [operate.md](operate.md). 낱말이 낯설면 [glossary.md](glossary.md).

## 1. 설치 전 준비

### 서버

| 항목 | 조건 |
|---|---|
| 운영 체제 | 리눅스, x86_64. Windows·macOS 의 Docker Desktop 은 지원하지 않는다 |
| Docker Engine | 24.0 이상 |
| 프로세서 | 2코어 이상 |
| 메모리 | 4 GB 이상, 그리고 고를 구역의 권장 메모리 합계 이상 |
| 디스크 | 여유 10 GB 이상(20 GB 미만은 경고) |
| 시각 | 동기화돼 있을 것(틀리면 인증서 발급과 로그인이 실패할 수 있다) |

Docker Compose 는 따로 깔지 않아도 된다 — 설치 관리자 이미지에 든 것을 쓴다.

구역별 권장 메모리(출처는 `backend/app/zones.json`):

| 구역 | 권장 메모리 |
|---|---|
| 기본(항상 설치) | 4 GB |
| 메일 | +1 GB |
| 채팅 · 일정·연락처·할 일 | 추가 없음 |
| 문서 편집·위키·게시판 | +2 GB |
| 회의 | +1 GB |
| 코드 저장소 | +0.5 GB |
| AI 도우미 | +1 GB |
| 애드온: SSO·LDAP 제공 | +0.5 GB |
| 애드온: 격리 브라우저 | +0.1 GB |

묶음으로는 최소 4 GB, 협업 7 GB, 전체 9.5 GB 다. "4 GB 서버"처럼 실제로 보이는 메모리가 조금 모자란 경우(차이 8% 안)는 4 GB 로 쳐 준다.

### 접속 주소와 DNS

**접속 주소**는 사람들이 브라우저에 입력할 주소다(예: `workspace.example.com`). 도메인 이름을 쓰는 것이 기본이고, 시험용이라면 IP 주소로도 설치할 수 있다(이 경우 임시 인증서만 된다).

설치 전에 DNS 에 A 레코드를 등록해 둔다.

| 이름 | 언제 필요한가 |
|---|---|
| `workspace.example.com` (접속 주소) | 항상 |
| `mail.<메일 도메인>` | 메일 구역을 내장 메일 서버로 쓸 때 |
| `turn.<접속 주소>` | 회의 구역에서 중계 서버를 쓸 때 |
| `rbi.<접속 주소>` | 격리 브라우저 애드온을 쓸 때 |

인증서를 자동 발급으로 받으면 위에서 해당하는 이름이 **모두** 인증서에 들어간다. 그 가운데 DNS 에 없는 이름이 하나라도 있으면 발급 전체가 실패한다.

내장 메일 서버를 쓰면 메일 도메인에 레코드 다섯 개(MX, A, SPF, DKIM, DMARC)가 더 필요하다. 값은 마법사의 메일 화면이 보여 준다 — 지금 다 등록하지 못해도 설치는 계속된다.

### 포트

밖에서 이 서버로 들어와야 하는 포트다. 클라우드의 보안 그룹, 서버 방화벽, 공유기에서 열어 준다.

| 구역 | 포트 | 쓰임 |
|---|---|---|
| 기본 | 80/tcp | 인증서 발급과 접속 |
| | 443/tcp | 접속(앞단 프록시 뒤라면 프록시가 받는다) |
| 메일(내장 메일 서버) | 25/tcp | 메일 받기 |
| | 465/tcp, 587/tcp | 메일 보내기 |
| | 993/tcp | 메일 읽기(IMAP) |
| 회의 | 7882-7892/udp | 영상과 음성 |
| | 7881/tcp | 영상과 음성(UDP 가 막힌 참가자) |
| | 3478/udp | 중계 |
| | 4433/udp | 무손실 오디오를 켰을 때만 |
| 코드 저장소 | 2222/tcp | 저장소 접속(SSH) |
| SSO·LDAP 제공 | 636/tcp | 계정 조회(LDAPS). 평문 389 는 기본으로 서버 자신에게만 열린다 |

- 설치하는 동안에는 **8443/tcp**(설치 마법사)에도 닿아야 한다. 설치가 끝나면 마법사는 잠기고, 이 포트는 방화벽에서 닫아도 된다.
- 이 서버가 직접 접속을 받는 구성에서는 회의 중계의 보안 연결이 **5349/tcp** 에 열린다(443 은 웹이 쓴다).
- 통신사가 25번 포트를 막는 회선에서는 내장 메일 서버로 메일을 주고받을 수 없다. 외부 발신 서버를 고른다.

### 연결 형태

마법사가 서버의 주소를 보고 감지하지만, 미리 알아 두면 좋다.

| 연결 형태 | 뜻 | 준비할 것 |
|---|---|---|
| 공인 주소에 직접 연결 | 클라우드 서버처럼 서버가 공인 주소를 직접 가진다 | 위 포트를 방화벽에서 연다 |
| 공유기 뒤 (포트 포워딩) | 서버가 사설 주소를 쓰고 공유기가 앞에 있다 | 공유기에서 위 포트를 이 서버로 넘긴다. 마법사가 구역을 고른 뒤 목록을 보여 준다 |
| 기존 프록시 뒤 | 이미 쓰는 리버스 프록시가 앞에 있다 | 프록시의 주소(또는 대역). 아래 참고 |

프록시 뒤 구성에서 알아 둘 것:

- 프록시를 거치는 것은 웹 접속뿐이다. 이 서버는 80번에서 평문으로 받고, 인증서는 프록시가 맡는다.
- 프록시는 접속자의 주소를 `X-Real-IP` 머리말로 넘겨야 한다(`X-Forwarded-For` 만으로는 접속자 주소로 쓰지 않는다). WebSocket 과 큰 파일 올리기도 통과시켜야 한다. 마법사의 프록시 주소 화면에 nginx 설정 예시가 있다.
- 메일·회의·코드 저장소(SSH)·LDAP 포트는 프록시를 거치지 않고 이 서버로 바로 들어와야 한다.

### 인증서

| 방식 | 언제 | 조건 |
|---|---|---|
| 자동 발급 (Let's Encrypt) | 직접 연결·공유기 뒤 | 접속 주소가 도메인이고 이 서버를 가리켜야 하며, 밖에서 80번으로 닿아야 한다 |
| 가지고 있는 인증서 올리기 | 직접 연결·공유기 뒤 | 인증서(중간 인증서까지 이어 붙인 PEM)와 개인 키(암호가 걸리지 않은 PEM). 접속 주소가 들어 있어야 한다 |
| 프록시가 처리 | 기존 프록시 뒤 | 프록시에 인증서가 있다. 이 서버에서는 발급하지 않는다 |
| **임시 인증서**로 설치하고 나중에 발급 | 접속 주소가 아직 이 서버를 가리키지 않거나 확인할 수 없을 때, 주소가 IP 일 때, 자동 발급이 실패했을 때 | 없음 |

임시 인증서는 자체 서명이라 브라우저가 경고를 보여 준다. 설치를 마친 뒤 관리 › 보안·SSL 의 인증서 카드에서 발급하거나 올린다([operate.md](operate.md#5-인증서)). 임시 인증서인 동안에는 코드 저장소의 로그인 연동이 "연결 보류"로 남는다.

### 파일 저장 위치

파일 탭의 문서, 채팅 첨부, 메일 첨부 보관본이 놓이는 곳이다. **설치 후에 옮기려면 전체를 복사해야 하니 지금 정한다.** 데이터베이스와 메일함은 어느 쪽을 골라도 이 서버의 디스크에 둔다.

| 선택 | 준비할 것 |
|---|---|
| 이 서버의 디스크 | 없음. 원하면 이미 있는 폴더를 지정할 수 있다(절대 경로, 쓸 수 있어야 한다) |
| 네트워크 저장소 (NFS) | 아래 |

NFS 준비물:

- **NFSv4.1** 을 지원하는 NAS 나 파일 서버. v3 만 되는 서버는 붙지 않는다.
- 이 서버의 주소에 **읽기·쓰기**를 허용한 공유(내보내기) 경로.
- 공유의 뿌리를 **uid/gid `1000:1000`** 이 쓸 수 있을 것. 설치 관리자는 공유 뿌리의 소유자·권한을 바꾸지 않는다.
- 이 서버에서 NAS 의 TCP 2049 에 닿을 것.

마법사가 다섯 가지(닿는가, 붙일 수 있는가, 쓰기·읽기·지우기, 파일 잠금, 여유 공간)를 검사하고, 앞의 네 가지가 통과해야 다음으로 간다.

## 2. 설치

### 설치 관리자 띄우기

```bash
docker run -d --name jw-installer --restart unless-stopped \
  -p 8443:8443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /opt/just-workspace:/data \
  -e JW_HOST_DIR=/opt/just-workspace \
  -e JW_INSTALLER_VERSION=1.0.0 \
  ghcr.io/just-workspace/just-workspace-installer:1.0.0

docker logs jw-installer
```

- `/opt/just-workspace` 가 **설치 폴더**다. 다른 경로를 써도 되지만 `-v <폴더>:/data` 와 `-e JW_HOST_DIR=<폴더>` 는 반드시 같은 경로여야 한다.
- `-e JW_INSTALLER_VERSION=<버전>` 에는 **이미지 태그와 같은 버전**을 적는다. 설치 관리자가 설치할 제품 버전이다. 안정판 이미지는 검증을 마친 시험판 이미지를 다시 빌드하지 않고 그대로 승격한 것이라, 이 값을 주지 않으면 이미지 안에 구워진 시험판 버전 글자(`1.0.0-beta.N`)를 자신의 버전으로 안다(그때는 설치 관리자의 로그 첫머리에 한 줄 알림이 나온다).
- `-e JW_PUBLIC_HOST=<서버 주소>` 를 주면 로그의 주소와 설치 관리자의 인증서에 그 값을 쓴다.
- 위 이미지는 첫 릴리스와 함께 공개된다. 그 전에는 [소스에서 빌드해 설치](#소스에서-빌드해-설치)한다.

로그에 이런 줄이 나온다.

```
 브라우저에서 여세요:  https://<서버 주소>:8443/?token=XXXXXXXXXXXX
 SHA-256 지문: AB:CD:…
```

그 주소를 브라우저로 연다. 설치 관리자의 인증서는 자체 서명이라 경고 화면이 뜬다 — 경고 화면에서 인증서의 SHA-256 지문을 로그의 값과 대조하고 진행한다.

### 설치 마법사의 화면

왼쪽의 단계 목록은 고른 값에 따라 늘거나 준다. 브라우저를 닫아도 입력한 값은 서버에 남아 있고, 다시 들어오면 이어서 한다.

| 화면 | 하는 일 |
|---|---|
| 설치 토큰 | 로그의 주소로 들어오면 거치지 않는다. 주소를 직접 입력했다면 토큰(영문 대문자와 숫자 12자리)을 적는다 |
| 사전 점검 | 서버를 점검한다. **실패**가 없어야 다음으로 간다. **주의**는 그대로 두고 진행할 수 있다 — [문제 해결](#사전-점검에서-걸렸을-때) |
| 시작 방식 | **새로 설치** · **빠른 설치** · **백업에서 복원** 가운데 하나. 답변 파일로 설치하는 방법도 여기서 안내한다 |
| 접속 주소와 연결 | 접속 주소를 입력하면 이 서버를 가리키는지 확인한다. 연결 형태와 인증서 방식을 고른다 |
| 프록시 주소 | (기존 프록시 뒤일 때) 프록시의 주소나 대역. 여러 개는 쉼표로 나눈다 |
| 인증서 올리기 | (인증서를 올릴 때) 인증서와 개인 키 파일. 접속 주소·키 짝·만료일을 바로 확인한다 |
| 파일 저장 위치 | 이 서버의 디스크 또는 네트워크 저장소 (NFS) |
| 구역 선택 | 묶음(최소·협업·전체)을 고르거나 직접 고른다. 권장 메모리 합계가 서버 메모리를 넘으면 다음으로 갈 수 없다. 선택 애드온도 여기서 고른다 |
| 포트 포워딩 안내 | (공유기 뒤일 때) 공유기에서 이 서버로 넘길 포트 목록 |
| 메일 | (메일 구역) 내장 메일 서버 + 메일 도메인, 또는 외부 발신 서버(SMTP). 내장이면 등록할 레코드 다섯 개와 지금 상태를 보여 준다 |
| 회의 | (회의 구역) 공인 주소, 중계 서버 사용 여부, 무손실 오디오 |
| AI 도우미 | (AI 도우미 구역) 지금 연결(제공자와 키) 또는 나중에 |
| 코드 저장소 | (코드 저장소 구역) 받을 버전 — 검증된 버전 · 최신 · 직접 지정 |
| 관리자 계정 | 이름, 아이디, 비밀번호(12자 이상). 이 워크스페이스의 첫 계정이다 |
| 요약 | 고른 내용과 주의할 점, 열리는 포트. **아직 서버에 바뀐 것은 없다.** 고급 설정(내부 네트워크 대역)과 답변 파일 내려받기가 여기 있다 |
| 적용 | 설치를 누르면 단계별로 진행한다: 설정 파일과 비밀 키 만들기 → 저장소 연결 → 이미지 받기 → 데이터베이스 준비 → 인증서 발급 → 구역 시작 → 관리자 계정 만들기 → 마법사 잠그기 |
| 완료 | 접속 주소와 다음에 할 일 |

적용은 브라우저를 닫아도 계속된다. 한 단계가 실패하면 원인과 고치는 방법이 화면에 나오고, 고친 뒤 **"이 단계부터 다시"** 를 누르면 끝난 단계는 건드리지 않고 이어 간다. 인증서 자동 발급이 실패하면 임시 인증서로 계속하는 선택지가 나온다.

비밀값(암호화 키, 데이터베이스 비밀번호, 구역끼리 쓰는 키)은 설치 관리자가 만든다. 직접 정할 것은 관리자 비밀번호뿐이다.

### 빠른 설치

시작 방식에서 **빠른 설치**를 고르면 접속 주소, 메일, 관리자 계정만 묻는다. 나머지는 감지한 값과 기본값으로 둔다.

- 연결 형태: 감지한 값.
- 인증서: 접속 주소가 이 서버를 가리키면 자동 발급, 아니면 임시 인증서.
- 파일 저장 위치: 이 서버의 디스크.
- 구역: 협업 묶음. 서버 메모리가 모자라면 최소 묶음으로 내리고 메일 화면을 건너뛴다.

구역은 설치 후 관리 › 구역에서 켜고 끌 수 있다.

### 무인 설치 (답변 파일)

마법사의 답과 같은 내용을 JSON 파일 하나로 적어 화면 없이 설치한다. 요약 화면의 "답변 파일 내려받기"로 지금 고른 값을 파일로 받을 수도 있다(비밀번호와 키는 들어가지 않는다).

최소 묶음, 임시 인증서:

```json
{
  "version": 1,
  "mode": "new",
  "access": { "domain": "workspace.example.com", "network": "direct", "cert": "temporary" },
  "storage": { "kind": "local" },
  "preset": "minimal",
  "addons": [],
  "admin": { "name": "관리자", "username": "admin" }
}
```

협업 묶음, 자동 발급, 내장 메일 서버:

```json
{
  "version": 1,
  "mode": "new",
  "access": { "domain": "workspace.example.com", "network": "direct", "cert": "auto" },
  "storage": { "kind": "local" },
  "preset": "collab",
  "addons": [],
  "mail": { "kind": "builtin", "mail_domain": "example.com" },
  "admin": { "name": "관리자", "username": "admin" }
}
```

NFS 저장소는 `"storage": { "kind": "nfs", "server": "192.168.10.30", "export": "/volume1/workspace" }`, 프록시 뒤는 `"access": { "domain": "…", "network": "proxy", "proxy_addresses": ["192.168.10.5"], "cert": "proxy" }` 로 적는다. 모든 항목은 [installer.md](installer.md) 4절, 견본은 `installer/e2e/answers/` 에 있다.

파일을 설치 폴더에 두고(컨테이너 안에서는 `/data/` 아래로 보인다) 실행한다. 관리자 비밀번호 같은 비밀은 파일에 적지 않고 환경변수로 넘길 수 있다 — `JW_ADMIN_PASSWORD`, `JW_MAIL_PASSWORD`, `JW_AI_API_KEY`.

```bash
# /opt/just-workspace/answers.json 에 답변 파일, /opt/just-workspace/admin.env 에 JW_ADMIN_PASSWORD=<비밀번호> (권한 600)
docker exec jw-installer jw apply --answers /data/answers.json --dry-run     # 검증만 — 아무것도 바꾸지 않는다
docker exec --env-file /opt/just-workspace/admin.env jw-installer jw apply --answers /data/answers.json
rm /opt/just-workspace/admin.env

docker exec jw-installer jw status          # 단계별 상태
```

### 소스에서 빌드해 설치

미리 빌드한 이미지가 공개되기 전이거나, 고친 소스로 설치하려는 경우다. 설치할 서버에서:

```bash
git clone https://github.com/just-workspace/just-workspace.git
cd just-workspace
bash installer/e2e/build-images.sh      # 우리 이미지 전부 + 설치 관리자를 소스로 빌드한다

docker run -d --name jw-installer --restart unless-stopped \
  -p 8443:8443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /opt/just-workspace:/data \
  -e JW_HOST_DIR=/opt/just-workspace \
  -e JW_REGISTRY=localhost \
  -e JW_INSTALLER_VERSION=$(cat VERSION) \
  just-workspace-installer:$(cat VERSION)
```

- 빌드에는 서버에 git 과 Docker Compose 플러그인(`docker compose`)이 있어야 한다. 시간과 디스크가 꽤 든다.
- 스크립트는 `localhost/just-workspace-<이름>:<버전>` 과 `just-workspace-installer:<버전>` 을 만든다(검수에 쓰는 것과 같은 스크립트다). `JW_REGISTRY=localhost` 는 설치 관리자에게 서버에 이미 있는 그 이미지를 쓰라고 알린다.
- 다른 곳에서 만든 구성 요소(데이터베이스, 문서 편집기 등)는 이 경우에도 원 배포처에서 받는다.
- 격리 브라우저 애드온의 세션 이미지는 무거워서 따로 빌드한다: `bash installer/e2e/build-images.sh rbi-mirror`.
- 설치 관리자 이미지에는 리포의 `installer/keys/*.pub`(업데이트 채널의 서명을 확인하는 공개 키)가 들어간다. 그 폴더를 비우고 빌드했다면 관리 › 업데이트가 "구성되지 않음"으로 나온다. 다른 채널을 쓰려면 `docker exec -i jw-installer jw update-key add - < release.pub` 로 그 채널의 공개 키를 넣는다(설치 폴더의 키가 이미지의 키보다 우선한다) — [operate.md](operate.md#2-업데이트)의 "업데이트 확인이 구성되지 않았습니다".

## 3. 설치 뒤 할 일

완료 화면이 해당하는 것을 알려 준다.

1. **접속 주소로 들어가 로그인한다.** 설치 마법사는 잠겼고, 이제부터 설정은 관리 화면에서 바꾼다.
2. **인증서 발급** — 임시 인증서로 설치했다면 접속 주소가 이 서버를 가리키게 한 뒤 관리 › 보안·SSL 의 인증서 카드에서 발급한다.
3. **빠진 메일 레코드 등록** — 관리 › 구역의 메일 설정에서 등록할 레코드와 지금 상태를 다시 볼 수 있다.
4. **백업 설정** — 관리 › 저장소·백업에서 예약 백업을 켠다. 백업은 서버 밖에도 한 벌 둔다.
5. **사람 초대** — 메일 주소로 초대하거나 초대 링크를 만든다.
6. **8443 닫기** — 설치 마법사의 포트는 방화벽에서 닫아도 된다. 설치 관리자 컨테이너(`jw-installer`)는 **지우지 않는다** — 구역 켜고 끄기, 업데이트, 인증서 갱신 뒤 처리를 이 컨테이너가 한다.

## 4. 문제 해결

### 사전 점검에서 걸렸을 때

| 항목 | 통과 조건 | 걸리면 |
|---|---|---|
| Docker Engine | 24.0 이상 | (실패) Docker 를 올린다. "Docker 에 연결하지 못했습니다"면 Docker 가 실행 중인지, `docker run` 에 `-v /var/run/docker.sock:/var/run/docker.sock` 을 줬는지 본다 |
| Docker Compose | 2.20 이상 | (실패) 설치 관리자 이미지에 든 것을 쓰므로 공식 이미지에서는 걸리지 않는다 |
| 프로세서 | 2코어 이상 | (실패) 코어를 늘린다 |
| 메모리 | 4 GB 이상, 고른 구역의 권장 합계 이상 | (실패) 구역을 줄이거나 서버 메모리를 늘린다 |
| 프로세서 종류 | x86_64 | (실패) x86_64 서버에 설치한다 |
| 디스크 여유 공간 | 10 GB 이상 | (실패) 쓰지 않는 Docker 이미지와 파일을 지운다. 20 GB 미만은 주의 |
| 시간 동기화 | 동기화됨 | (주의) 서버의 시간 동기화(chrony, systemd-timesyncd 등)를 켠다 |
| 웹 포트 80 · 443 | 비어 있음 | (실패) 그 포트를 쓰는 다른 프로그램(다른 웹 서버 등)을 중지한다. 443 은 이 서버가 직접 받을 때만 본다 |
| 메일 포트 25 | 비어 있음 | (주의) 내장 메일 서버를 쓰려면 그 프로그램(호스트의 postfix 등)을 먼저 중지한다. 메일을 쓰지 않으면 그대로 진행한다 |
| 내부 네트워크 대역 | 서버의 다른 네트워크와 겹치지 않음 | (실패) 요약 화면의 고급 설정에서 다른 /24 대역으로 바꾼다(기본 `172.28.0.0/24`) |
| 인터넷 연결 · 이미지 저장소 | 닿음 | (주의) 이미지가 이 서버에 이미 있으면 진행할 수 있다 |
| SELinux | (정보) | 상태만 보여 준다. SELinux 가 켜진 배포판에서의 설치는 아직 확인하지 못했다 |

### 토큰이 만료됐거나 잃어버렸을 때

설치 토큰은 만든 지 24시간이 지나면 쓸 수 없다. 5번 틀리면 30초 동안 받지 않는다. 다시 발급한다:

```bash
docker exec jw-installer jw token
```

새 토큰이 든 주소가 나온다. 옛 토큰은 무효가 되고, 입력해 둔 답은 그대로다.

### 적용이 실패했을 때

- 화면에 나온 원인을 고치고 **"이 단계부터 다시"** 를 누른다. "기록 내려받기"로 그 단계의 기록을 받을 수 있다.
- 기록은 서버의 `<설치 폴더>/state/logs/<단계>.log` 에도 있다. 알려진 비밀값은 `***` 로 가려져 있다.
- 터미널에서는 `docker exec jw-installer jw status` 와 `docker logs jw-installer`.
- 이미지를 받지 못했다면 서버가 인터넷에 나갈 수 있는지 본다.
- 인증서 자동 발급이 실패했다면 접속 주소(와 `mail.`·`turn.`·`rbi.` 이름)가 이 서버를 가리키는지, 밖에서 80번으로 닿는지 본다. 급하면 임시 인증서로 계속하고 나중에 발급한다.

### 처음부터 다시 설치

```bash
docker exec jw-installer jw reinstall          # 지울 목록만 보여 준다
docker exec jw-installer jw reinstall --yes    # 지우고 설치 관리자를 다시 시작한다
docker logs jw-installer                       # 끝에 새 설치 토큰
```

**계정·파일·메일·대화가 모두 지워진다.** 워크스페이스의 컨테이너·볼륨·내부망과 설치 폴더의 `stack`·`state` 가 대상이다. 파일 저장 위치가 NFS 나 지정 폴더면 그 안의 파일은 지우지 않는다(다만 새 설치의 계정과 이어지지 않는다).

### 관리자 비밀번호를 잊었을 때

```bash
docker exec jw-installer jw reset-admin <아이디>                  # 임시 비밀번호가 화면에 한 번 나온다
docker exec jw-installer jw reset-admin <아이디> --disable-2fa    # 인증 앱도 잃어버렸을 때
```

관리자 계정에만 쓴다. 그 계정의 열린 세션은 모두 끊긴다. 일반 계정의 비밀번호는 관리 화면에서 재설정한다.

### 설치 마법사가 "설치가 이미 끝났습니다"라고 할 때

설치가 끝난 서버의 8443 은 잠겨 있다. 설정은 접속 주소로 로그인한 뒤 관리 화면에서 바꾼다.
